## 1. 개요

### 1.1 기능 요약

여러 증권사·기관에 흩어진 보유 자산을 하나로 모아, **종목·섹터·시장·통화·계좌** 축으로 비중과 손익을 보여준다. 보유 ETF는 구성종목으로 분해(look-through)해 실제 익스포저를 계산한다.

평가금액·손익은 **EOD 일배치**로 계산한다(실시간 아님). 사용자는 필요할 때 수동 새로고침으로 온디맨드 동기화를 트리거한다.

### 1.2 축

보유 자산의 **현재 상태**를 여러 기준으로 집계해 보여준다. 지원 축과 각 축이 요구하는 데이터는 다음과 같다. (기간 기준 집계는 그레인이 달라 별도 원장에서 다룬다 — §1.4)

| 축 | 값 | 필요 데이터 | 원천 |
|---|---|---|---|
| 계좌 | 계좌 단위 | 계좌 마스터 | KIS · CODEF |
| 계좌유형 | 일반 / 연금 | 계좌 마스터 | KIS · CODEF |
| 종목 | 종목 단위 | 종목 마스터(ISIN) | 데이터팀 종목 마스터 |
| 섹터 | 반도체 · 소프트웨어 · … | 종목 → 섹터 분류 | yfinance(미국) · Naver 업종(국내) |
| 시장 | 국내 / 미국 | 종목 마스터 메타 | 종목 마스터 |
| 통화 | KRW / USD | 종목 마스터 메타 + 환율 | 종목 마스터 · python-kis `exchange_rate` |
| 자산군 | 주식 / ETF / 현금 | 종목 마스터 메타 | 종목 마스터 |
| 레버리지 | 레버리지 여부 | 종목 속성 | 미확보 — 확보 시 활성화 |

축과 별개로 **렌즈**가 하나 있다. 축이 집계 기준을 바꾸는 반면, 렌즈는 집계 대상 행 자체를 바꾼다.

| 렌즈 | 동작 | 필요 데이터 | 원천 |
|---|---|---|---|
| `DIRECT` | ETF를 한 종목으로 집계 | — | — |
| `LOOK_THROUGH` | ETF를 구성종목으로 분해 | ETF 구성종목 · 비중 | SPDR XLSX(미국) · 국내 원천 확보 전제 |

### 1.3 그레인

축은 8개지만 저장 단위는 하나다. 모든 축은 (계좌 × 종목)보다 거칠고, 증권사 잔고도 이 단위로 들어온다.

```
position_line  ── 그레인: (as_of, 계좌, 종목)
```

한 행이 계좌 하나와 종목 하나를 가리키므로, 두 마스터를 조인하면 **§1.2의 축 8개가 모두 결정된다.**

| 축 | 유도 |
|---|---|
| 계좌 · 계좌유형 | `account_id` → 계좌 마스터 |
| 종목 · 섹터 · 시장 · 통화 · 자산군 · 레버리지 | `instrument_id` → 종목 마스터 |

축은 이렇게 행에 딸린 속성이고, 뷰는 그 위의 `GROUP BY`다.

| 뷰 | group_by |
|---|---|
| 요약 | (없음) |
| 종목별 | 종목 |
| 비중 분석 | 섹터 / 시장 / 통화 / 자산군 / 종목 |
| 계좌별 | 계좌유형 → 계좌 |

축을 늘리는 일은 `group_by`에 컬럼 이름을 하나 더 쓰는 일이다. 섹터·자산군 같은 분류 축은 라인에 복사하지 않고 마스터에서 조인한다. 분류를 보정하면 과거 스냅샷에도 소급 반영된다.

### 1.4 원장

그레인이 다른 데이터는 같은 팩트에 담기지 않는다. 실현손익은 체결 1건 단위, 자산 변화는 기간 단위여서 `position_line`에 들어갈 수 없다. 원장을 셋으로 나눈다.

| 원장 | 그레인 | 축 | 답하는 것 | 확보 |
|---|---|---|---|---|
| 보유 스냅샷 `position_line` | as_of × 계좌 × 종목 | §1.2의 8개, **확장됨** | 현재 상태 전부 | 항상 — 잔고가 진실 |
| 현금흐름 `cashflow` | 계좌 × 유형 × 일시 | 기간 × 유형, 고정 | 자산 변화의 원인 | 입출금내역 |
| 거래 `trade` | 체결 1건 | 기간 × 종목, 고정 | 실현/미실현 분해 | 구간별 불완전 |

축이 늘어나는 원장은 보유 스냅샷뿐이다. **앞의 축(§1.2~1.3)과 뒤의 저장 규칙(§1.5)은 이 원장에 적용된다.** 나머지 두 원장은 축 조합이 고정이라 그레인 정의로 끝난다.

확보 난이도가 서로 다르므로 분리는 리스크 격리도 겸한다. 6개 뷰 중 4개(요약 · 종목별 · 비중 분석 · 계좌별)는 보유 스냅샷만 사용한다. 실현손익만 거래 원장에 의존해 신뢰도 등급이 붙고(§4.4), 자산 변화는 스냅샷과 현금흐름으로 기간 손익을 구하므로 거래 원장 없이 성립한다(§2.9).

### 1.5 저장 규칙

**금액과 수량만 저장한다.** 비율은 가산이 불가능해 라인에 두면 축이 바뀔 때 값이 틀어진다. 평가손익·수익률·비중 컬럼은 스키마에 만들지 않고 집계 후에 계산한다.

| 저장 (가산 O) | 파생 (집계 후) |
|---|---|
| `quantity` · `cost_amount_*` · `market_value_*` | 평가손익 = Σ평가 − Σ매입 |
| | 평가손익률 = 평가손익 ÷ Σ매입 |
| | 비중 = Σ평가 ÷ 전체 Σ평가 |

**원화 환산값은 라인에 기록한다.** `market_value_krw`를 `fx_rate` · `fx_as_of`와 함께 저장한다. 집계 시점에 환산하면 통화가 섞인 그룹에서 적용 환율이 모호해진다.

**렌즈는 라인 집합을 라인 집합으로 바꾼다.** 입출력 스키마가 같으므로 하위의 집계·비중·환산 로직은 렌즈 적용 여부와 무관하다.

```
DIRECT        [TIGER 미국나스닥100  512,000]
                    │
LOOK_THROUGH  [AAPL 148,000] [MSFT 121,000] … [기타 16,000]     Σ 보존
```

### 1.6 용어 (Glossary)

| 용어 | 의미 |
|------|------|
| **그레인 (grain)** | 팩트 테이블의 한 행이 무엇을 나타내는가. 차원 모델링(dimensional modeling)의 표준 용어. 집계가 중복·누락 없이 한 번씩 일어나게 하는 기준 |
| **팩트 (fact)** | 측정값을 담는 행 집합. `position_line`이 스냅샷 원장의 팩트 |
| **축 (axis)** | 집계의 그룹핑 기준. 계좌·계좌유형·종목·섹터·시장·통화·자산군 |
| **측정값 (measure)** | 더해도 되는 값. 수량·매입금액·평가금액 |
| **파생 지표 (derived)** | 더할 수 없는 값. 평가손익률·비중. 집계 **후**에만 계산 |
| **렌즈 (lens)** | 라인 집합을 라인 집합으로 바꾸는 변환. `DIRECT` / `LOOK_THROUGH` |
| **원장 (ledger)** | 서로 다른 진실의 출처. 보유 스냅샷 / 현금흐름 / 거래 |
| **신뢰도 등급 (grade)** | 거래 원장의 완전성 판정. `VERIFIED / SEEDED / UNAVAILABLE / CONFLICT` |
| **as-of** | 그 행이 나타내는 시점. 스냅샷의 기준일자이자 `position_line` 그레인의 일부. 적재 시각, 계좌별 실제 데이터 시각(`source_as_of`)과 구분 |
| **캐리포워드** | 동기화 실패 시 직전 성공 스냅샷을 그날 기준시각으로 이월 |

## 2. 뷰 모델

### 2.1 뷰 목록

뷰의 정체성은 **답하는 질문**과 **그레인** 두 가지로 정의된다.

| 뷰 | 답하는 질문 | 그레인 | 원장 | 렌즈 |
|---|---|---|---|---|
| **요약** | 지금 내 자산 상태는? | 포트폴리오 전체 1행 | 스냅샷 | 미니차트 한정 |
| **종목별** | 뭘 얼마나 갖고, 각각 얼마 벌었나? | 종목 1행(계좌 합산) | 스냅샷 | 선택 |
| **비중 분석** | 내 돈이 어디에 쏠려 있나? | 축 값 1행 | 스냅샷 | **전면** |
| **계좌별** | 어느 기관·계좌유형에 뭐가 있나? | 계좌 1행 | 스냅샷 | 없음 |
| **실현손익** | 이번 달/올해 확정한 손익은? | 기간 × 종목 1행 | 거래 | 없음 |
| **자산 변화** | 는 게 벌어서인가, 넣어서인가? | 기간 × 현금흐름 유형 | 스냅샷 + 현금흐름 | 없음 |

하위 화면: **종목 상세**, **계좌 연동·동기화**.

앞의 4개 뷰는 같은 팩트를 그룹핑만 바꾼 것이다(§1.3). 실현손익과 자산 변화만 다른 원장을 쓴다.

### 2.2 네비게이션

하단 탭바는 **5개**다 — 요약 · 종목 · 비중 · 계좌 · 손익(실현손익). **자산 변화는 탭이 아니다.**

탭 6개는 하단바에 과밀하고, 무엇보다 자산 변화는 **질문이 생긴 순간에 도달해야 의미가 있는 화면**이다. 진입 경로를 두 곳의 맥락 링크로 고정한다.

| 진입점 | 링크 |
|---|---|
| 요약 — 총자산 증감 옆 | `이번 달 자산 +800만원   왜? →` |
| 실현손익 — 목록 하단 | `이 기간 전체 투자손익 보기 →` |

종목 상세와 계좌 연동도 탭이 아니라 하위 화면이다(각각 종목별 행 탭, 계좌별 화면에서 진입).

### 2.3 공통 전역 요소

모든 뷰 상단에 고정된다.

- **as-of 배너**: `기준 2026-07-27 15:30 · 새로고침`. 배치 실행 기준시각이며 수동 동기화 진입점을 겸한다.
- **환율 표기**: 원화 환산에 적용한 환율과 기준시점을 배너에 병기한다. 통화 표시 규칙은 §3.7.
- **지연 배너**: 캐리포워드된 계좌가 있으면 `1개 계좌가 07-26 기준입니다`.

### 2.4 요약

| | |
|---|---|
| 그레인 | 포트폴리오 전체 1행 |
| 지표 | 총자산(총평가+예수금) · 총매입 · 총평가손익(금액/%) · 현금비중 · 전일 대비 일간 변화 · 계좌수·종목수 |
| 보조 | 자산구성 미니차트(시장 또는 자산군) |
| 렌즈 | 미니차트에만 적용 |

일간 변화는 EOD 1회 배치이므로 **전일 EOD 스냅샷과의 차이**로 정의된다. 장중 실시간 등락이 아니며, 라벨에 `전일 종가 대비`를 명시한다.

총자산 증감 옆에 `왜? →` 링크를 두어 자산 변화 뷰로 유도한다. 총자산 변화는 입출금을 포함하므로 수익과 같지 않다.

### 2.5 종목별

| | |
|---|---|
| 그레인 | **종목 1행 (모든 계좌 합산)** |
| 컬럼 | 종목명 · 시장 배지 · 수량 · 평단 · 현재가 · 매입금액 · 평가금액 · 평가손익(금액/%) · 비중 |
| 통화 | 외화 종목은 현지 통화와 원화를 병기(§3.7). 합계·비중은 원화 |
| 필터 | 계좌 / 시장 / 자산군 |
| 정렬 | 평가금액 내림차순(기본) |
| 렌즈 | 선택 — "구성종목 기준으로 보기" |
| 하위 | 행 탭 → 종목 상세 |

같은 종목을 여러 계좌에 보유하면 **항상 합산해 1행으로 표시**하고, 평단은 수량가중평균으로 계산한다. 계좌별 분해는 종목 상세에서 제공한다.

### 2.6 비중 분석

| | |
|---|---|
| 그레인 | 축 값 1행 |
| 축 | 종목 · 섹터 · 시장(국내/미국) · 통화 · 자산군(주식/ETF/현금) · 레버리지(원천 확보 시) |
| 지표 | 평가금액(원화) · 비중% · 종목수 |
| 렌즈 | **핵심 용처.** 기본 `DIRECT`, 토글로 `LOOK_THROUGH` |
| 시각화 | 도넛 + 순위 막대 리스트 |

렌즈를 켜면 **`기타(현금·파생·미매칭)` 버킷이 함께 표시**되어 합이 항상 100%가 되게 한다. ETF가 보유한 현금·선물·채권, weight 합의 반올림 오차, 종목 마스터에 매칭되지 않는 구성종목이 여기 들어간다. 이는 데이터 확보 실패가 아니라 **원래 종목이 아닌 것**이므로 별도 버킷으로 유지한다.

렌즈를 켜면 배너에 구성비중 파일의 기준일을 병기한다 (§3.4).

### 2.7 계좌별

| | |
|---|---|
| 그레인 | 계좌 1행 |
| 컬럼 | 기관 · **계좌유형(일반/연금)** · 기준통화 · 평가금액 · 예수금 · 평가손익 · 비중 · 마지막 동기화 · 연동 상태 |
| 그룹 | **계좌유형별 소계** (일반 합계 / 연금 합계) |
| 렌즈 | 없음 |
| 하위 | 행 탭 → 종목별 뷰(계좌 필터 적용 상태) |
| 겸용 | 계좌 연동·재인증·해제의 진입점 |

렌즈는 계좌 합계를 바꾸지 못한다(look-through는 총합을 보존하므로). 따라서 이 뷰에는 렌즈를 노출하지 않는다.

### 2.8 실현손익

| | |
|---|---|
| 그레인 | 기간 × 종목 1행 |
| 원장 | 거래 원장 전용 |
| 기간 | 이번 달 · 지난달 · 올해 · 작년 · 지정 |
| 컬럼 | 종목 · 매도일 · 매도금액 · 취득원가 · 실현손익(금액/%) · **신뢰도 배지** |
| 통화 | 종목 행은 병기, 기간 합계는 원화(§3.7) |
| 렌즈 | 없음 (ETF는 ETF 단위로 체결됨) |

**미실현 평가손익은 이 뷰에 넣지 않는다.** 요약(총평가손익)과 종목별(종목당 평가손익)에서 이미 제공되며, 기간 확정값과 시점 평가값을 한 화면에서 더하면 어떤 질문에도 답하지 않는 숫자가 나온다.

실현손익만 보면 이익 난 종목만 매도한 착시가 생기므로, 하단에 `이 기간 전체 투자손익 보기 →` 링크로 자산 변화 뷰를 연결한다.

합계는 확보된 계좌만 합산하고 `미포함 계좌 N개`를 함께 표시한다. 조용히 제외하지 않는다.

### 2.9 자산 변화

| | |
|---|---|
| 그레인 | 기간 × 현금흐름 유형 |
| 원장 | 보유 스냅샷 + 현금흐름 |
| 기간 | 이번 달 · 올해 · 지정 |
| 구성 | 기초자산 → 넣은 돈 → 번 돈 → 계좌 편입·제외 → 기말자산 (워터폴) |
| 렌즈 | 없음 |

**항등식**

```
기말 총자산 = 기초 총자산
            + 넣은 돈          입금 - 출금
            + 번 돈            투자손익 + 배당 - 수수료·세금
            ± 계좌 편입·제외
```

투자손익은 **나머지 전부**로 정의한다.

```
투자손익 = Δ총자산 - (입금 - 출금) - 배당 + 수수료·세금 - 계좌 편입·제외
```

우변에 거래 원장이 들어가지 않는다. 스냅샷 두 개(기초·기말)와 현금흐름만 있으면 기간 손익이 나오므로, **체결내역 조회가 차단된 계좌(연금 등)도 정확한 손익을 얻는다.** 거래 원장은 그 손익을 실현/미실현으로 쪼갤 때만 필요하다. 이 뷰가 거래내역 불완전에 대한 백스톱 역할을 한다.

**투자손익의 범위** — 기간 중 매도해 확정된 손익과, 기말까지 보유한 자산의 평가 변동을 합한 값이다. 후자는 미실현손익 자체가 아니라 그 **변화분**(기말 미실현 - 기초 미실현)이다. 따라서 실현손익 뷰의 숫자와 일치하지 않는다.

**배당과 수수료는 "번 돈"에 넣는다.** 이 뷰가 답하는 질문이 "는 게 벌어서인가 넣어서인가"이므로, 자산이 낳은 배당과 투자에 든 비용은 시장 쪽에 귀속된다. 사용자가 넣은 돈은 입출금뿐이다.

**화면 구성**

```
┌─────────────────────────────────────────────┐
│ ‹  자산 변화            [이번 달 ▾]          │
├─────────────────────────────────────────────┤
│   자산이 800만원 늘었는데                     │
│   600만원은 넣은 돈이고, 200만원을 벌었어요    │
├─────────────────────────────────────────────┤
│  기초자산                    5,000만  ▉      │
│                                             │
│  넣은 돈                      +600만        │
│    + 입금                     +600만    ▉▉  │ 파랑
│    - 출금                        0          │
│                                             │
│  번 돈                        +200만        │
│    ± 투자손익                 +191만      ▉ │ 초록·강조
│    + 배당                      +12만      ▏ │ 초록
│    - 수수료·세금                -3만      ▏ │ 회색
│  ────────────────────────────────────       │
│  기말자산                    5,800만  ▉▉▉▉  │
├─────────────────────────────────────────────┤
│  투자손익 191만원의 내역                      │
│   확정(실현)          +85만   실현손익 뷰 →   │
│   평가(미실현) 변화   +106만                  │
│   ※ 일부 계좌는 거래내역이 없어 분해 생략      │
├─────────────────────────────────────────────┤
│  기준 2026-07-27 15:30 · 기초 2026-06-30     │
└─────────────────────────────────────────────┘
```

**UX 원칙**

1. **답을 문장으로 먼저 준다.** 차트를 읽기 전에 질문이 해결되어야 한다.
2. **넣은 돈과 번 돈을 두 덩어리로 가른다.** 색도 이 경계를 따른다 — 사용자가 넣은 돈은 파랑, 시장이 만든 돈은 초록.
3. **투자손익만 강조한다.** 나머지 항목은 근거이고 답은 하나다.
4. **분해는 아래로 미룬다.** 실현/미실현 분해는 거래 원장이 필요한 불확실 영역이므로 확실한 답 아래에 보조로 둔다.

이 뷰가 존재하는 결정적 이유는 **자산이 늘었는데 손실인 상황**이다. 다른 어떤 뷰로도 드러나지 않는다.

```
자산이 200만원 늘었지만
350만원을 넣고 150만원을 잃었어요
```

**경계 처리**

| 상황 | 처리 |
|---|---|
| 기초 스냅샷 없음 | 가장 이른 스냅샷을 기초로 쓰고 `2026-07-15부터 계산`처럼 실제 시작일을 표시 |
| 기간 중 계좌 연동 | `＋ 계좌 편입` 항목. 금액은 그 계좌 첫 스냅샷의 총자산 |
| 기간 중 계좌 해제 | `－ 계좌 제외` 항목. 금액은 마지막 스냅샷의 총자산 |
| 기간 경계에 이월 계좌 | 경고 표시. 그 시점의 참값을 모르므로 오차는 정량화하지 않는다 |
| 현금흐름 미확보 계좌 | 경고 표시(§4.6). 그 계좌의 입출금이 투자손익에 섞인다 |
| 값이 0인 항목 | 행을 숨긴다 |

계좌 편입·제외는 사용자가 넣은 돈도 시장이 만든 돈도 아니므로 두 덩어리 어디에도 넣지 않고 별도로 표시한다.

### 2.10 종목 상세 (하위 화면)

보유 요약 · **계좌별 분해**(계좌마다 다른 평단) · 해당 종목 거래내역과 실현손익 · 기업행위 이력.

## 3. 집계 모델

### 3.1 팩트 그레인

```
position_line  ── 그레인: (as_of, account_id, instrument_id)
```

모든 스냅샷 기반 뷰가 이 행 집합 하나를 읽는다. 그레인이 고정되어야 집계가 중복·누락 없이 한 번씩 일어난다.

### 3.2 가산성 규칙

비율은 더할 수도 평균낼 수도 없다.

```
삼성전자    매입 1,000만  평가 1,100만  → +10%
SK하이닉스  매입   100만  평가   130만  → +30%

라인별 수익률 평균 = (10 + 30) / 2             = +20%     ← 틀림
집계 후 계산       = (1,230 − 1,100) / 1,100   = +11.8%   ← 맞음
```

| 저장 (가산 O) | 파생 (집계 후) |
|---|---|
| quantity · cost_amount_* · market_value_* | 평가손익 = Σ평가 − Σ매입 |
| | 평가손익률 = 평가손익 ÷ Σ매입 |
| | 비중 = Σ평가 ÷ 전체 Σ평가 |

**파생 지표는 스키마에 컬럼을 만들지 않는다.** 자리가 없으면 잘못 더할 방법도 없다. 규칙을 문서가 아니라 테이블 구조로 강제한다.

### 3.3 축

축 값은 **논리적으로는 라인의 속성이지만, 물리적으로는 마스터 조인**으로 얻는다. `position_line`은 `account_id`·`instrument_id`만 갖고 섹터·시장·통화·자산군은 `instrument`/`account` 마스터에서 조인한다.

분류를 라인에 복사하면 오분류가 과거 스냅샷에 영구히 박혀 되돌릴 수 없다. 섹터 체계 통일 매핑은 아직 미해결이라 보정이 여러 번 예상되므로, **분류 보정이 과거 화면에도 소급 반영되는 쪽**을 택한다. 보유 규모상 조회 시 집계로 충분하므로 별도 집계 캐시는 두지 않는다.

### 3.4 렌즈

렌즈는 **입력도 라인 집합, 출력도 라인 집합인 변환 함수**다. 출력 스키마가 입력과 동일하므로 하위 집계·비중·환산 로직은 변경되지 않는다.

```
DIRECT       : [TIGER나스닥100  평가 500만]
                     │ lens = LOOK_THROUGH
                     ▼ ETF 1행 → 구성종목 N행으로 안분 (총합 보존)
LOOK_THROUGH : [AAPL 45만] [MSFT 40만] ... [기타 15만]
```

중첩 ETF(ETF가 다른 ETF를 보유)는 **평탄화된 구성비중으로 제공받는다.** 재귀 분해·깊이 제한·순환 참조 차단은 구성비중 산출 단계에서 처리되므로, 전개는 `ETF 평가금액 × 최종 구성비중` 한 겹 곱셈으로 끝난다.

전개는 **조회 시 수행하고 항상 최신 구성비중을 사용한다.** 구성비중이 갱신되면 화면 값도 따라 바뀐다(§3.3의 소급 반영과 동일 원칙). 전개 결과나 적용한 구성비중 버전은 저장하지 않는다.

**렌즈는 뷰의 속성이 아니라 지표의 속성이다.** 금액 기반 구성 비중을 다루는 곳에만 붙는다. 총자산·총손익·계좌 합계는 렌즈를 걸어도 값이 변하지 않으므로(총합 보존), 해당 뷰에는 렌즈를 노출하지 않는다.

**분해 후 컬럼별 유효성**

| 컬럼 | LOOK_THROUGH | 근거 |
|---|---|---|
| 평가금액 · 비중 | 유효 | 총합 보존 |
| 수량 | 환산수량으로 표시 | `(ETF 평가금액 × 구성비중) ÷ 구성종목 현재가`. 소수점이며 개별 매도 불가 → "환산" 표기 |
| 매입금액 | 안분값으로 표시 | ETF 원가를 현재 구성비중으로 안분 → "안분" 표기 |
| **평단가** | **정의 불가 — 컬럼 숨김** | 아래 참조 |
| **평가손익률** | **정의 불가 — 컬럼 숨김** | 평단에 의존 |

**평단가가 원리적으로 성립하지 않는 이유**는 데이터 부족이 아니라 정의 자체의 문제다.

1. 매입 시점의 구성비중이 필요하나 **구성비중 시계열은 공개되지 않는다**(운용사는 최신 파일만 배포).
2. ETF는 계속 리밸런싱되므로 **보유 기간 중 구성종목이 변동**한다. 매수한 적 없는 종목이 현재 구성에 있을 수 있고, 매수 당시 있던 종목이 지금은 빠졌을 수 있다.
3. 분할 매수 시 **회차마다 구성이 다르다**.

현재 비중으로 ETF 원가를 안분한 값은 계산할 수 있으나, 사용자가 그 가격에 매수한 적이 없는 허구의 숫자다. 평단이 허구이면 평가손익률도 허구가 된다.

**분해 결과는 근사값이다.** 잔고 스냅샷의 기준시각과 ETF 구성비중 파일의 기준일이 어긋나므로(구성비중은 전일자 등), 분해된 평가금액과 비중은 그 시차만큼 오차를 포함한다. 렌즈를 켠 화면에는 **두 기준시각을 함께 표기**한다.

```
기준 2026-07-27 15:30 · 구성비중 기준 2026-07-26
```

### 3.5 뷰 사양

뷰는 코드가 아니라 사양 데이터다.

```json
{ "view_key": "sector_weight",
  "lens": "LOOK_THROUGH",
  "group_by": ["sector"],
  "metrics": ["market_value_krw", "weight_pct", "unrealized_pnl_krw"],
  "filters": { "account_type": "PENSION" } }
```

"국내/미국 비중"은 `group_by: ["market"]`, "연금계좌만 섹터 비중"은 필터 추가로 끝난다. 뷰 추가에 API·테이블·파이프라인이 늘지 않는다.

### 3.6 처리 파이프라인

배치에서 만드는 것은 `position_line` 하나뿐이고, 렌즈 전개부터는 조회할 때마다 수행한다.

| 단계 | 하는 일 | 입력 → 출력 | 시점 | 담당 |
|---|---|---|---|---|
| 0 | 잔고·구성종목 수집, 종목 마스터 갱신, 구성비중 중첩 평탄화 | 증권사 API · 운용사 파일 → 원본 · 마스터 | EOD 배치 | 데이터 |
| 1 | 잔고를 계좌×종목 행으로 정규화. 매입·평가금액 계산, 원화 환산, 예수금을 `CASH` 종목으로 편입, 실패 계좌 이월 | 원본 잔고 · 환율 → `position_line` | EOD 배치 · 수동 동기화 | 백엔드 |
| 2 | ETF 행을 구성비중대로 안분. 미매칭·비중 미달분을 기타 버킷으로. 총합 보존 검증 | `position_line` · 구성비중 → 전개 라인 | 조회 시 | 백엔드 |
| 3 | 종목·계좌 마스터를 조인해 축 값 부여 | 전개 라인 · 마스터 → 축이 붙은 라인 | 조회 시 | 백엔드 |
| 4 | 요청 축으로 `GROUP BY` + 측정값 `SUM` | 축이 붙은 라인 → 축 값별 합계 | 조회 시 | 백엔드 |
| 5 | 평가손익 · 손익률 · 비중 계산 | 축 값별 합계 → 파생 지표 | 조회 시 | 백엔드 |
| 6 | 통화 선택, 평가금액순 정렬, 기타 버킷을 맨 끝에 배치, as-of · 구성비중 기준일 첨부 | 파생 지표 → 응답 | 조회 시 | 백엔드 |

- `DIRECT` 렌즈는 2단계를 건너뛰고 `position_line`이 그대로 3단계로 간다.
- 같은 종목의 직접보유분과 ETF 경유분은 4단계에서 합쳐진다.
- 실현손익 뷰는 `realized_pnl_line`을, 자산 변화 뷰는 `position_line` 두 시점과 `cashflow`를 읽으므로 2~3단계를 거치지 않는다.

### 3.7 통화 표시

집계 값은 **항상 원화**로 표시한다. 통화가 다른 금액은 더할 수 없으므로(§1.5 가산성), 여러 통화가 섞일 수 있는 묶음에는 현지 통화 표시가 성립하지 않는다.

묶음 안에 통화가 하나뿐일 때만 현지 통화를 병기한다.

| 묶음 | 단일 통화 | 표시 |
|---|---|---|
| 종목 1행 | ✓ | `$198.20 · 274,000원` 병기 |
| 통화 축 그룹 | ✓ | 해당 통화로 표시 |
| 섹터 · 시장 · 자산군 · 계좌 · 포트폴리오 전체 | ✗ | 원화만 |

"미국 자산이 달러로 얼마인가"는 비중 분석에서 통화 축을 선택해 확인한다. 그 그룹은 정의상 단일 통화다.

## 4. 3원장과 신뢰도 등급

### 4.1 원장별 역할

| 원장 | 그레인 | 답하는 것 | 확보 |
|---|---|---|---|
| **보유 스냅샷** `position_line` | (as_of, 계좌, 종목) | 현재 상태 전부 | 항상 확보 — 잔고가 진실 |
| **현금흐름** `cashflow` | (계좌, 유형, 일시) | 자산 변화의 원인 | KIS·CODEF 입출금내역 |
| **거래** `trade` | 체결 1건 | 실현/미실현 **분해** | 구간별 불완전 |

현재 보유 상태는 **증권사 잔고 조회가 유일한 진실의 원천**이며 거래내역에서 역산하지 않는다. 액면분할·증자·배당재투자에서 오차가 누적되고, 거래가 하나라도 누락되면 전체가 틀어지기 때문이다.

### 4.2 뷰별 원장 의존도

| 뷰 | 스냅샷 | 현금흐름 | 거래 | 등급 노출 |
|---|---|---|---|---|
| 요약 | ● | | | 없음 |
| 종목별 | ● | | | 없음 |
| 비중 분석 | ● | | | 없음 |
| 계좌별 | ● | | | 없음 |
| **실현손익** | | | ● | **있음** |
| **자산 변화** | ● | ● | ○ (분해 시만) | 잔차로 표현 |

6개 뷰 중 4개가 **항상 신뢰 가능한 원장만** 사용한다. 거래내역 불완전 리스크는 실현손익 뷰 한 곳에 갇힌다.

### 4.3 평단 재구성과 실현손익

- **평단**: 거래내역 기반 **이동가중평균**.
- **매도 시**: `실현손익 = (매도가 − 평단) × 수량 − 비용`.
- **기업행위 보정**: `corporate_action`을 `ex_date` 기준으로 수량·단가에 반영한다. 분할이 매수와 매도 사이에 끼면 평단이 부호까지 틀어진다(예: 10주@100 → 2:1 분할 → 20주@50인데 거래내역에는 매수 10@100만 남음).
- **불완전 거래내역 보정**: 거래내역이 포지션 개시 시점부터 확보되지 않으면 잔고 스냅샷의 평단을 출발 평단(seed)으로 삼아 보정한다.

### 4.4 신뢰도 등급 — 계산 가능한 판정

등급은 감으로 붙이지 않고 **(계좌 × 종목)마다 역산해서 판정**한다.

```
opening_qty = 현재 보유수량 − Σ(확보구간 매수) + Σ(확보구간 매도)   ← 기업행위 보정 후
```

확보된 거래내역을 현재 잔고에서 거꾸로 되감았을 때 시작 시점 수량이 0이면, 그 구간이 곧 포지션 전체다.

| 등급 | 판정 | 실현손익 | UI |
|---|---|---|---|
| **VERIFIED** | `opening_qty = 0` | 신뢰 | 배지 없음 |
| **SEEDED** | `opening_qty > 0` → 잔고 평단을 시드로 보정 | 추정값 | **"추정" 배지** |
| **UNAVAILABLE** | 거래내역 미확보 | 미제공 | "거래내역 없음" |
| **CONFLICT** | `opening_qty < 0` (수량 모순) | 미제공 | 경고 + 동기화 유도 |

**직교 플래그** `ca_unknown`: 보유 기간 중 기업행위가 있었을 정황인데 이력이 없으면 `VERIFIED`여도 경고를 덧붙인다. 등급은 "거래가 다 있는가", 플래그는 "그 거래를 올바로 해석했는가"를 판정하므로 성격이 다르다.

### 4.5 SEEDED 표시 정책

조회 기간 한계와 기관별 제공 범위 때문에 **상당수 계좌가 SEEDED에 해당한다.** 따라서 숨기지 않고 **표시하되 배지로 구분**한다.

- 종목 행에 `추정` 배지
- 합계 하단에 `N개 종목은 추정치입니다`
- 배지 탭 시 사유 설명 — 거래내역 확보 구간 시작일과 시드 평단 출처

### 4.6 현금흐름의 커버리지

기간 내 해당 계좌의 입출금 내역을 확보했는지 **계좌 × 기간** 단위로 판정한다. 조회에 성공했고 요청 기간이 원천의 지원 범위 안일 때만 확보로 본다.

미확보 계좌의 입출금은 투자손익에 섞이므로(§2.9에서 투자손익은 나머지 전부로 정의됨) 자산 변화 뷰에 경고를 표시한다.

```
1개 계좌의 입출금 내역이 없어 투자손익에 섞여 있을 수 있어요
```

잔차 항목은 두지 않는다. 투자손익이 나머지 전부로 정의되어 항등식에 잔차가 생길 자리가 없다.

### 5.2 예수금을 종목으로 취급한다

`instrument.asset_class = CASH`인 통화별 의사종목(`KRW 예수금`, `USD 예수금`)을 두고, 예수금도 `position_line`에 넣는다.

이렇게 하면 **총자산·현금비중·자산군 축이 모두 같은 팩트 하나에서 나온다.** 예수금을 별도 테이블로 분리하면 "총자산 = 평가 + 예수금"을 화면마다 다시 조립해야 하고, 자산군 비중 차트에서 현금만 특수 처리하게 된다.

### 5.3 원화 환산은 라인에 머티리얼라이즈한다

`market_value_krw`를 라인 생성 시점에 계산해 저장하고 `fx_rate`·`fx_as_of`를 함께 기록한다. 집계 시점에 환율을 곱하면 여러 통화가 섞인 그룹에서 어떤 환율을 적용할지 모호해지지만, 라인 단위에서 환산해두면 단순 합산으로 끝난다.

**이것이 '환율 기준시점 관리' 요구사항의 구현 전부다** — 별도 기능이 아니라 컬럼 두 개.

**1차 정의 고정**: 매입시점 환율은 자동 확보가 어려우므로, **원화 평가손익은 "가격손익 + 환손익 혼재값"**으로 정의한다. 둘을 분리하지 않으며 이 사실을 UI에 고지한다.

### 5.4 스냅샷 누적

`position_line`은 하루에 한 벌씩 쌓인다. `as_of`는 일자 단위이며, 당일 행은 동기화할 때마다 갱신하고 과거 `as_of` 행은 수정하지 않는다. 당일 값은 잠정치이고 EOD 배치가 확정치다.

자산 변화 뷰가 기초자산을 꺼내려면 과거 스냅샷이 필요하고, 요약 뷰의 일간 변화도 전일 스냅샷에 의존한다. 부수 효과로 자산 추이 시계열이 같은 저장소에서 나온다.

## 6. 카탈로그

뷰가 6개로 고정이므로 운영자 UI 없이 **코드 시드 상수**로 둔다.

```
Axis    { key, label, source, applicable_views[], lens_sensitive }
          account · account_type · instrument · sector · market
          · currency · asset_class · is_leveraged(원천 확보 시)

Metric  { key, label, additive, formula, requires_ledger }
          additive=false 지표는 group_by 결과에만 적용 가능하도록 강제

View    { view_key, question, grain, group_by[], metrics[],
          lens_policy: NONE | OPTIONAL | ALWAYS, ledgers[] }
```

`lens_policy`가 렌즈 노출을 한 곳에서 통제한다. 뷰 컴포넌트가 각자 판단하지 않는다.

| 뷰 | lens_policy |
|---|---|
| 요약 | `OPTIONAL` (미니차트 한정) |
| 종목별 | `OPTIONAL` |
| 비중 분석 | `OPTIONAL` |
| 계좌별 · 실현손익 · 자산 변화 | `NONE` |

**서빙 계약**

뷰 사양은 서버가 보유한다. 클라이언트는 `view_key`와 카탈로그에 정의된 파라미터만 보낸다.

```
GET /portfolio/views/allocation?axis=sector&lens=look_through
GET /portfolio/views/positions?lens=direct
```

`Axis.applicable_views`와 `View.lens_policy`가 곧 허용 파라미터 목록이므로 검증은 카탈로그 대조로 끝난다. 임의 조합을 받는 범용 쿼리 엔드포인트는 두지 않는다.

## 7. 계좌 연동 · 동기화

### 7.1 두 경로

| | KIS (본인 계좌) | CODEF (타 기관) |
|---|---|---|
| 입력 | 본인 앱키·시크릿·계좌번호 | 기관 선택 + 인증서 또는 ID/PW |
| 저장 | 앱키(암호화 저장) | **Connected ID만** — 인증정보는 CODEF만 보유 |
| 전송 | — | 프론트에서 CODEF 공개키로 RSA 암호화 후 전송 |
| 특성 | 빠르고 안정적 | 스크래핑 기반 — 느리고 실패 가능 |
| 재시도 | 레이트리밋 스로틀 중심 | 지수 백오프 + 부분 실패 허용 |

1차에서는 자동 연동만 지원한다. 수동 입력·CSV 업로드는 제공하지 않으며, 연동 불가 계좌는 안내만 표시한다.

### 7.2 계좌 상태 기계

```
                  ┌──────────────┐
   연동 시작 ─────▶│  CONNECTING  │
                  └──────┬───────┘
                    성공 │    추가인증 요구
                         ▼         ▼
                  ┌───────────┐  ┌──────────────────┐
        ┌────────▶│ CONNECTED │  │ REAUTH_REQUIRED  │◀── 인증 만료
        │         └─────┬─────┘  └────────┬─────────┘
        │        배치/수동│                 │ 재인증
        │               ▼                 │
        │         ┌───────────┐           │
        └─────────│  SYNCING  │───────────┘
          성공     └─────┬─────┘
                   실패  ▼
                  ┌───────────┐      사용자 해제
                  │  FAILED   │────▶ DISCONNECTED
                  └───────────┘      (과거 라인 보존)
```

### 7.3 캐리포워드 — 실패해도 라인은 만든다

계좌 동기화가 실패해도 **그날의 `position_line`은 반드시 생성한다.** 직전 성공 스냅샷을 그날 `as_of`로 복제하고 `source_as_of`·`is_carried_forward`로 표시한다.

1. **그레인 유일성이 유지된다.** `as_of`마다 모든 계좌가 정확히 1행씩 있어야 총자산·비중이 성립한다. 빠뜨리면 그날만 총자산이 급락해 손실처럼 보인다.
2. **자산 변화 뷰가 깨지지 않는다.** 기초·기말 스냅샷이 항상 존재해야 항등식이 성립한다.
3. **오차가 정직하게 흘러간다.** 이월된 평가금액은 낡은 시세이지만, 그 오차는 다음 성공 동기화 시 자산 변화 뷰의 `설명되지 않는 변화`로 드러난다.

### 7.4 as-of의 두 층

| 층 | 의미 | 노출 |
|---|---|---|
| **화면 as-of** | 배치 실행 기준시각 | 모든 뷰 상단 배너 (단일) |
| **`source_as_of`** | 계좌별 실제 데이터 시각 | 계좌별 뷰, 지연 시 전역 배너 |

집계는 단일 as-of 기준으로 정렬하고, 계좌마다 동기화 시각이 다른 현실은 두 번째 층에서 표현한다.

### 7.5 부분 실패 시 표시 정책

| 상황 | 총자산 | 표시 |
|---|---|---|
| 일부 계좌 실패 | **포함**(이월값) | 요약 상단 `1개 계좌가 07-26 기준입니다` |
| 재인증 필요 | 포함(이월값) | 계좌별 뷰 배지 + 재인증 CTA |
| 연동 해제 | **제외** | 자산 변화 뷰에 `계좌 연동 해제 −X원` 별도 항목 |

실패 계좌를 총자산에서 제외하면 자산이 급감해 더 큰 오해를 낳는다. **포함하되 낡았다고 말하는 쪽**이 안전하다. 연동 해제는 사용자가 의도한 행위이므로 제외하되, 손실로 오인되지 않게 자산 변화 뷰에서 별도 항목으로 분리한다.

연동 해제 시 과거 `position_line`은 보존한다(soft delete). 삭제하면 과거 기간의 자산 변화 계산이 불가능해진다.

### 7.6 동기화 트리거

| 트리거 | 범위 | 응답 |
|---|---|---|
| EOD 일배치 | 전 계좌 | — |
| 수동 새로고침 | 전 계좌 또는 단일 계좌 | `202` 즉시 반환 → 완료 시 푸시/폴링 |
| 재인증 완료 | 해당 계좌 | 즉시 트리거 |

동기화는 무겁고 느리므로 **항상 비동기**다. 새로고침은 즉시 응답하고 진행 상태만 표시한다.

| UI 요소 | 모델 경로 | 비고 |

| as-of 배너 | 배치 실행 기준시각 | 모든 뷰 공통 |
| 통화 토글 | `market_value_local` ⇄ `market_value_krw` | 전역 상태 유지 |
| 적용 환율 표기 | `fx_rate` · `fx_as_of` | 원화 모드에서만 |
| 지연 배너 | `is_carried_forward` 集計 | 이월 계좌 존재 시 |
| 새로고침 | `sync_run` 생성 | `202` 비동기 |

### 8.2 뷰

| UI 요소 | 모델 경로 |
|---|---|
| 총자산 | `Σ market_value_krw` (CASH 포함) |
| 총평가손익 | `Σ market_value − Σ cost_amount` |
| 일간 변화 | 당일 `as_of` 총자산 − 전일 `as_of` 총자산 |
| 종목 비중 | `Σ market_value_krw ÷ 전체 Σ` (group_by instrument) |
| 섹터 비중 | 동일, `group_by sector` + `instrument` 조인 |
| 렌즈 토글 | `View.lens_policy = OPTIONAL` 인 뷰에서만 노출 |
| 구성비중 기준일 | `etf_constituent.as_of` |
| 계좌유형 소계 | `group_by account_type` |
| 실현손익 행 | `realized_pnl_line` |
| 신뢰도 배지 | `position_basis.grade` → `realized_pnl_line.grade` |
| 워터폴 막대 | `cashflow.type` 별 합계 |
| 투자손익 | `Δ총자산 − 순입금 − 배당 + 수수료` |
| 설명되지 않는 변화 | 항등식 잔차 |

## 9. 검증 규칙

저장·집계 전 **앱 계층에서 반드시 통과**해야 한다.

### 9.1 팩트 정합성

| 규칙 |
|---|
| `position_line`은 (as_of, account, instrument)마다 **정확히 1행** — 그레인 유일성 |
| 비율 성격 컬럼(수익률·비중)은 스키마에 존재 불가 |
| `market_value_krw`가 있으면 `fx_rate`·`fx_as_of` 필수 (null 금지) |
| 동기화 실패 계좌도 해당 `as_of`에 라인 존재 (캐리포워드) |
| `is_carried_forward = true`이면 `source_as_of < as_of` |
| `as_of`는 일자 단위. 당일 외의 `as_of` 행은 수정 불가 |
| 현지 통화 표시는 묶음이 단일 통화일 때만 허용. 그 외 집계 값은 원화 |

### 9.2 렌즈

| 규칙 |
|---|
| look-through 전개 후 `Σ market_value`가 전개 전과 일치 (총합 보존, 기타 버킷 포함) |
| `etf_constituent` 재귀 깊이 제한 + 순환 참조 차단 |
| `LOOK_THROUGH` 결과에는 평단·평가손익률 필드가 존재하지 않음 |
| 렌즈 적용 화면은 `etf_constituent.as_of`를 반드시 함께 노출 |

### 9.3 등급

| 규칙 |
|---|
| 등급 판정은 `corporate_action` 반영 **후**의 수량으로 계산 |
| `realized_pnl_line.grade`는 `position_basis.grade`와 항상 일치 |
| `SEEDED`이면 `seed_avg_price` 필수 |
| `UNAVAILABLE`·`CONFLICT` 종목은 실현손익 합계에서 제외하되 제외 건수를 노출 |

### 9.4 자산 변화

| 규칙 |
|---|
| 기간 양 끝의 `position_line` 필요. 기초가 없으면 가장 이른 스냅샷으로 대체하고 실제 시작일 표시 |
| 투자손익은 나머지 전부로 정의 — 별도 잔차 항목을 두지 않는다 |
| 계좌 편입·제외는 손익이 아닌 별도 항목. "넣은 돈"·"번 돈" 어디에도 넣지 않는다 |
| 배당·수수료·세금은 "번 돈"에 귀속 |
| 현금흐름 미확보 계좌가 있으면 경고 표시 |
| 기간 경계 스냅샷에 캐리포워드 계좌가 있으면 경고 표시 |

## 10. 화면 상태 전수 (State Matrix)

와이어플로우는 해피패스만 시각화한다. 아래는 화면별 구현 대상 상태 전수.

| 화면 | 상태 |
|---|---|
| 요약 | default / **연동 계좌 없음(온보딩)** / 로딩 / **지연 배너**(캐리포워드) / 동기화 중 |
| 종목별 | default / **보유 종목 없음** / 필터 결과 없음 / 렌즈 ON(평단·손익률 컬럼 제거) |
| 비중 분석 | default / 축 전환 / 렌즈 ON(기타 버킷·구성비중 기준일 표기) / **구성종목 데이터 없음** |
| 계좌별 | default / **재인증 필요 배지** / 동기화 실패 배지 / 연동 해제 확인 |
| 실현손익 | default / **해당 기간 매도 없음** / 추정 배지 / **미포함 계좌 N개** / 전 계좌 UNAVAILABLE |
| 자산 변화 | default / **기초 스냅샷 없음 → 실제 시작일 표시** / **계좌 편입·제외** / **현금흐름 미확보 경고** / 기간 경계 이월 경고 / 손실 케이스 |
| 종목 상세 | default / 거래내역 없음 / 기업행위 경고(`ca_unknown`) |
| 계좌 연동 | 기관 선택 / 인증 입력 / **추가 인증 요구** / 연동 실패·재시도 / 연동 성공 |
| 동기화 | 진행 중 / **부분 실패** / 전체 실패 / 완료 |

> 뒤로·취소 이동은 각 화면 네비바의 `‹`로 일관 제공한다.

## 11. 미결 / 향후 확장 (YAGNI 경계)

초기 범위에서 **의도적으로 제외**한 것들.

- **벤치마크 비교**: KOSPI·S&P500 대비 상대 성과. 원천은 FinanceDataReader로 확보 가능하나 우선순위가 아니다.
- **섹터 내 PER/PBR 분위수**: 데이터 원천 미확정.
- **수동 입력·CSV 업로드**: 자동 연동만 지원. 연동 불가 계좌는 안내만.
- **기간수익률(TWR·MWR)**: 자산 변화 뷰가 절대금액 손익까지 답하므로 1차에서는 불필요.
- **배당손익 별도 지표**: 현금흐름 원장에 `DIVIDEND`로만 존재.
- **포트폴리오 스냅샷 비교·백테스트**: 후속 과제.
- **과거 시점 화면 재현**: 전개 결과와 적용한 구성비중 버전을 저장하지 않으므로 과거 날짜의 ETF 분해는 재현하지 않는다.
- **매입시점 FX 분리**: 원화 평가손익을 가격손익/환손익으로 분해하지 않는다(§5.3).

### 외부 의존 대기

| 항목 | 내용 |
|---|---|
| 국내 ETF 구성종목 원천 | 확보를 전제로 설계했다. 미확보 시 비중 분석의 `LOOK_THROUGH`가 국내 ETF에 한해 동작 불가 |
| 섹터 체계 통일 매핑 | 미국·국내 분류 체계 통일. 마스터 조인 방식이라 보정이 과거에 소급 반영됨(§3.3) |
| 기업행위 데이터 원천 | 미확보 시 `ca_unknown` 플래그가 광범위하게 표시됨 |
| 레버리지 구분 | 원천 확보 시 `instrument.is_leveraged` 축 활성화 |
