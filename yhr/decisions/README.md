# 결정 기록(ADR)

"무엇을 대신해 무엇을 골랐나"와 그 뒤에 드러난 것을 적는다. 규칙 자체는 설계서([specs/](../specs/))에 있고, 여기서는 링크한다.

모두 결정이 끝난 뒤 2026-11-16에 정리했다. 버린 대안이 당시 원천(설계 · 계획 · 회의 기록, 커밋)에 남아 있는 결정만 골랐다. 빌드 · 이미지 · 인프라 같은 작은 기술 선택은 백엔드 [기술 선택](https://github.com/stock-project-crew/back-end/blob/main/docs/tech-choices.md)에 있다.

앞의 세 개가 대표다 — 동시성(0001), 운영(0006), 질의 튜닝(0005).

| ADR | 결정 |
|---|---|
| [0001 리더 없는 다중 복제본](0001-leaderless-replicas.md) | 리더 선출 · 분산 잠금 대신, 모든 복제본이 모든 주기 작업을 돌리고 중복은 데이터 조건으로 막았다 |
| [0006 배포 중 스키마 호환](0006-schema-compat-during-deploy.md) | 별도 마이그레이션 Job 대신 기동 시 Flyway를 돌리고, 롤링 중 공존은 호환 규칙과 CI 정적 검사로 막는다 |
| [0005 조회 성능](0005-read-performance.md) | 집계 캐시나 데이터팀 표 인덱스 대신, 질의가 읽는 범위를 좁히는 쪽으로 질의 모양을 바꿨다 |
| [0002 보유 스냅샷 파이프라인](0002-snapshot-pipeline.md) | 처리 기록을 멱등 키로 두고 실패를 사유로 분류해 계좌 단위로 가두며, 잠금은 날짜 → 계좌 순서로 고정했다 |
| [0003 발송 대기열](0003-delivery-queue.md) | 메시지 브로커 대신 발송 행을 대기열로 쓰고 `FOR UPDATE SKIP LOCKED`와 임대로 집으며, 외부 호출은 트랜잭션 밖에서 했다 |
| [0004 조회 정합성](0004-read-consistency.md) | Java에서 행을 더하는 대신 `GROUPING SETS` 한 질의에서 행 · 소계 · 합계를 함께 낸다 |
| [0007 서버 세션과 토큰 회전](0007-server-session-token-rotation.md) | 무상태 JWT 12시간 대신 서버 세션과 30분 접근 토큰, 갱신마다 바뀌는 갱신 토큰을 골랐다 |
| [0008 입출금 멱등 키](0008-cashflow-idempotency-key.md) | POST와 서버가 만든 id 대신, 앱이 만든 id를 주소에 싣는 `PUT`을 골랐다 |

## 형식

각 ADR은 맥락 → 결정 → 검토한 대안 → 결과 → 돌아보며 순서다. "돌아보며"에는 그 뒤에 드러난 결함 · 사고 · 바꾼 결정과 고친 커밋, 아직 남은 것을 적는다. 잰 것은 숫자와 출처를, 재지 않은 것은 재지 않았다고 적는다.
