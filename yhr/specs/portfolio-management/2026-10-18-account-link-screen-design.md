# 계좌 연동 화면 설계 — `account-link`

[포트폴리오 스펙](2026-07-28-portfolio-management-spec.md) §2.7 · §7 · §10이 정한 "계좌 연동 · 해제는 계좌별 화면에서 들어가는 하위 화면에서 한다"를 앱 화면으로 만드는 설계다. 서버 쪽은 [KIS 계좌 등록 · 해제 API 설계](2026-10-16-account-link-api-design.md)(이하 API 설계)가 정했고 `back-end` main에 있다. 스펙과 이 문서가 다르면 스펙이 맞다. 스펙 문구를 해석한 곳은 [§8](#8-스펙을-이렇게-읽은-곳)에 모았다.

| 근거 | 위치 |
|---|---|
| 계좌별 화면 · 연동 진입점 | 스펙 §2.7 |
| 계좌 상태 · 수집 결과 · 표시 정책 | 스펙 §7.1 · §7.2 · §7.5 |
| 엔드포인트 · 오류 형태 · 인증 | 스펙 §8.1 · §8.5 · §8.6 · §8.8 |
| 화면 상태 전수 | 스펙 §10 |
| 화면 목록 · 계좌 탭 점 · 공통 이름 | [앱 정보 구조](../app-information-architecture.md)(이하 IA) §2.2 · §3 · §6.1 |
| `POST` · `DELETE` · `GET /accounts` 계약, 오류 코드, 첫 수집 시점 | API 설계 §2.1 · §2.3 · §3 |
| 와이어플로우 | [`wireflow_src.py`](wireflow_src.py) → [`wireflow.png`](wireflow.png) |

## 1. 범위

**만든다**

- 계좌 탭(계좌별 화면) 하단의 `계좌 연동 관리` 버튼.
- 연동 계좌 목록 화면 `account-link`: 목록 · 해제 · 추가 진입.
- KIS 계좌 등록 폼 화면 `account-link/new`.
- 계좌 탭의 점(IA §3).
- `GET /accounts` 응답 타입과 조회, 등록 · 해제 요청.

**만들지 않는다**

- CODEF 경로(기관 선택 · 1차 인증 · 추가 인증). 서버에도 없다(API 설계 §1).
- 재인증 경로. KIS는 추가인증이 없어 `POST /accounts/{id}/reauth`가 없다(API 설계 §1).
- 지금 동기화와 진행 표시. 수동 동기화(`POST /sync` · `GET /sync/{run_id}`)가 `back-end` main에 들어오면 붙인다. 자리만 정한다(§2.2).
- 화면 캡처 막기(§5.5).

**다른 기관.** 지금 경로는 KIS 하나다. 다른 기관(CODEF 경로 · 그 밖의 증권사)이 나중에 들어올 수 있으므로 구조가 KIS 하나를 전제로 굳지 않게 한다. 상품코드 · 기본 라벨 · 폼 칸처럼 KIS에만 맞는 규칙은 등록 폼 쪽에 모으고, 목록 화면은 서버가 준 `broker` · `label` · `account_type` · 상태만으로 그린다. 기관이 늘면 `＋ 계좌 추가`와 기관별 폼 사이에 기관 선택을 끼운다. 그 설계는 지금 하지 않는다.

### 2.2 화면별

**계좌 탭**

- 계좌 목록 맨 아래(계좌 묶음 다음)에 `계좌 연동 관리` 버튼을 둔다. 앱의 합계 줄은 목록 맨 위에 있다. 누르면 `account-link`가 루트 스택에 쌓인다.
- 계좌별 뷰가 비어 있을 때(`NO_ACCOUNTS` · `NO_HOLDINGS`)도 빈 상태 아래에 같은 버튼을 둔다. 첫 연동은 이 버튼으로만 시작하고, 첫 수집 전 사용자는 `NO_HOLDINGS`를 받는다(§8의 1).
- `계좌 연동 관리` 옆이 지금 동기화가 들어갈 자리다. 수동 동기화는 계좌별 화면에서 트리거한다(스펙 §2.3). 이번에는 그리지 않는다.

**`NO_ACCOUNTS` 보조 문구** (`EmptyState`의 `SUBTEXT`, 모든 화면 공통)

- `계좌 연동은 준비 중입니다`를 `계좌 탭의 계좌 연동 관리에서 연동할 수 있어요`로 바꾼다. 요약 · 종목별 · 비중 · 실현손익의 빈 상태에는 버튼을 두지 않는다. `account-link`로 들어가는 곳은 계좌별 화면뿐이다(IA §2.2).
- 계좌 탭에서는 보조 문구를 두지 않는다. 바로 아래 버튼이 같은 말을 한다. **구현 판단.**

**계좌 연동 (`account-link`)**

- 스택 화면이고 헤더는 `계좌 연동`이다(IA §6.1).
- `GET /accounts`의 계좌를 서버 순서(계좌유형, 라벨) 그대로 한 줄씩 보인다. 한 줄은 `라벨 · 상품(위탁 / 연금저축) · 상태 줄(§3.1) · 해제`다. 상품은 `account_type`으로 정한다(`GENERAL` → 위탁, `PENSION` → 연금저축). `env`가 `DEMO`인 계좌는 상품 옆에 `모의`를 붙인다. `REAL`과 `null`에는 붙이지 않는다.
- 목록 아래에 `＋ 계좌 추가`를 둔다.
- 뒤로 가면 계좌 탭이다.

**한국투자증권 연동 (`account-link/new`)**

- `account-link` 위에 쌓이는 스택 화면이다. 기관 선택은 없다.
- 칸은 앱키 · 앱 시크릿 · 계좌번호 · 모의투자 계좌 체크 · 라벨이다(§4). 칸 아래에 `위탁(01)·연금저축(22) 계좌만 연동할 수 있어요`를 둔다.
- `202`면 화면을 닫고 `account-link`로 돌아간다. 목록을 다시 받아 새 계좌가 `연동 중`으로 보인다.
- 실패하면 이 화면에 머문다(§3.3).
- 따로 둔 화면이라, 떠나면 입력값이 컴포넌트 상태와 함께 사라진다(§5.1).

**해제**

- 행의 `해제` → 확인 시트(`ConfirmSheet`) → `DELETE /accounts/{id}` → 무효화(§6.3).

## 3. 상태

### 3.1 목록 행의 상태 줄

`link_state`와 `last_collection.state`로 정한다.

| `link_state` | `last_collection` | 상태 줄 | 색 |
|---|---|---|---|
| `CONNECTING` | `null` · `REQUESTED` · `RUNNING` · `DONE` | 연동 중 · 다음 정기 수집 뒤 잔고가 반영돼요 | 보조 |
| `CONNECTING` | `FAILED` | 첫 수집에 실패했어요. 앱키·계좌번호를 확인하고 해제한 뒤 다시 등록해 주세요 | 경고 |
| `CONNECTED` | `FAILED`가 아님 | 연동됨 | 보조 |
| `CONNECTED` | `FAILED` | 연동됨 · `MM-DD` 수집 실패 (`as_of`) | 경고 |
| `REAUTH_REQUIRED` | — | 재인증 필요 | 경고 |

- `CONNECTING` + `DONE`은 수집은 끝났고 생성기가 아직 처리하지 않은 사이다. 연동 중으로 둔다.
- 첫 수집 실패의 복구는 해제 뒤 재등록뿐이다(API 설계 §2.3). 문구가 그 길을 말한다.
- `REAUTH_REQUIRED`는 KIS에서 생기지 않지만 타입에 있다. 문구만 두고 조치 버튼은 두지 않는다.
- 모르는 `state` 값은 `link_state`만으로 고른다(`CONNECTING` → 연동 중, `CONNECTED` → 연동됨).
- `failure_reason` 코드는 보이지 않는다.
- 성공 수집 시각은 적지 않는다. 스펙 §2.7이 동기화 기능 전까지 마지막 동기화 시각을 표시하지 않는다고 정했다.
- **구현 판단:** `CONNECTED`의 수집 실패를 날짜와 함께 보인다. 계좌별 화면의 이월 배지와 같은 사실을 관리 목록에서도 알아보게 한다.

수집 요일 · 시각은 데이터 쪽 일정이라 문구에 넣지 않는다.

### 3.2 목록 화면

| 상태 | 표시 |
|---|---|
| 로딩 | 행 스켈레톤 |
| 조회 오류 | `ErrorState` + 재시도 |
| 빈 목록 | `연동된 계좌가 없어요` + `＋ 계좌 추가` |
| 기본 | 행 목록 + `＋ 계좌 추가` |
| 해제 확인 | 시트 제목 `{라벨} 연동을 해제할까요?`, 본문 `총자산에서 빠지고, 지난 기록은 자산 변화에 남아요. 다시 연동하려면 앱키를 다시 넣어야 해요`, 버튼 `해제` · `취소` |
| 해제 중 | 시트의 `해제`가 로딩. 두 번 보내지 않는다 |
| 해제 실패(`503` · 네트워크 · 그 밖) | 시트를 닫지 않고 시트 안에 오류 한 줄(서버 `message` 또는 `NetworkError` 문구). `ConfirmSheet`에 선택 prop `error`를 더한다 |
| 해제 `403` | 시트를 닫고 목록을 다시 받는다. 이미 없는 계좌다 |

해제 성공(`204`)이면 시트를 닫고 §6.3대로 무효화한다.

### 3.3 폼 화면

**클라이언트 검사.** `연동하기`를 누를 때 검사하고, 칸을 고치면 그 칸의 오류를 지운다. 오류가 하나라도 있으면 요청을 보내지 않는다.

| 칸 | 규칙 | 문구 |
|---|---|---|
| 앱키 | 앞뒤 공백을 지운 값이 1 ~ 1,024자 | 비면 `앱키를 입력해 주세요`, 길면 `1,024자 이내로 입력해 주세요` |
| 앱 시크릿 | 같음 | 비면 `앱 시크릿을 입력해 주세요`, 길면 같음 |
| 계좌번호 | 숫자 10자리 | `계좌번호 10자리를 입력해 주세요` |
| 라벨 | 앞뒤 공백을 지운 값이 1 ~ 30자(코드 포인트 수) | 비면 `라벨을 입력해 주세요`, 길면 `30자 이내로 입력해 주세요` |

규칙은 서버 규칙(API 설계 §3.1)과 같다. 상품코드(01 · 22)는 검사하지 않는다. 서버가 판정하고 문구를 준다.

**서버 응답.** 문구는 서버 `message`를 그대로 쓰고(`client.ts` 관례), `code`로는 놓을 자리만 고른다.

| 응답 | 자리 |
|---|---|
| `202` | `account-link`로 돌아간다 |
| `400 UNSUPPORTED_ACCOUNT_PRODUCT` | 계좌번호 칸 아래 |
| `400 INVALID_ACCOUNT_REQUEST` · `409 ACCOUNT_ALREADY_LINKED` · `409 ACCOUNT_UNAVAILABLE` · `503 CREDENTIAL_STORE_UNAVAILABLE` · `500` · 그 밖 | 폼 위 한 줄. 봉투가 없으면 `요청을 처리하지 못했어요`(`client.ts`) |
| 네트워크 오류 | 폼 위 한 줄. `NetworkError` 문구 |
| `401` | `client.ts`의 전역 로그아웃. 폼은 화면과 함께 사라진다 |

- 실패하면 시크릿 칸만 비우고 앱키 · 계좌번호 · 라벨은 남긴다.
- 보내는 동안 `연동하기`가 로딩이고 다시 누를 수 없다.
- 보내는 동안 화면을 떠나면 응답을 화면에 반영하지 않는다. 성공이면 무효화(§6.3)는 한다.

### 3.4 계좌 탭의 점

- 계좌별 뷰 응답의 `notices`에 `STALE_ACCOUNTS`나 `REAUTH_REQUIRED`가 있으면 계좌 탭에 점을 단다(IA §3 · 스펙 §7.5). 숫자는 달지 않는다.
- 탭 바가 계좌별 뷰 조회(`useAccounts`, 키 `['accounts']`)를 같이 쓴다. 앱이 열리면 이 조회가 한 번 나간다.
- 첫 수집에 실패한 연동 중 계좌는 IA §3 조건에 없어 점을 켜지 않는다.
- `tabBarBadge`로 숫자 없는 점을 그리는 방법은 확인하지 않았다. 구현 때 확인한다.

## 4. 입력 폼

**계좌번호**

- 숫자 키패드. 입력에서 숫자만 남기고 10자리에서 자른다. 하이픈을 섞어 붙여 넣어도 숫자만 남는다.
- 화면에는 9자리째부터 `12345678-01`처럼 하이픈을 그어 보인다. 사용자는 하이픈을 넣지 않는다.
- 요청에는 숫자 10자리를 싣는다. 서버는 하이픈 유무를 가리지 않는다(API 설계 §3.1).

**모의투자 계좌**

- 체크박스 하나다. 기본은 체크하지 않은 상태이고 `env: "REAL"`을 싣는다. 체크하면 `"DEMO"`를 싣는다.
- KIS는 실전과 모의투자의 앱키가 다르고, 수집기는 이 값으로 부를 서버를 고른다(API 설계 §6.1). 서버와 앱키가 맞지 않으면 첫 수집이 실패할 것으로 본다(확인하지 않음).
- 자격증명이 아니므로 가리지 않는다. 실패해도 그대로 둔다.
- 연동한 뒤 바꾸려면 해제하고 다시 등록한다.

**라벨**

- 필수다. 기본 라벨만 쓰면 위탁 두 개가 `한국투자 위탁` · `한국투자 위탁 2`로 갈려 목록에서 구분이 안 된다.
- 계좌번호가 10자리가 되면 상품코드로 기본값을 라벨 칸에 채운다. `01` → `한국투자 위탁`, `22` → `한국투자 연금저축`. 그 밖의 코드는 채우지 않는다.
- 사용자가 라벨 칸을 한 번이라도 고쳤으면 채우지 않는다. 미리 채운 값 그대로면 계좌번호가 바뀔 때 새 기본값으로 바꾼다.
- 요청에는 언제나 `label`을 싣는다. 서버의 순번 붙이기(API 설계 §3.4)는 이 화면에서 쓰이지 않는다.

**요청**

```json
{ "app_key": "<공백 지운 앱키>", "app_secret": "<공백 지운 시크릿>",
  "account_number": "<숫자 10자리>", "env": "REAL" | "DEMO", "label": "<공백 지운 라벨>" }
```

## 5. 자격증명 입력값 다루기

### 5.1 보관

- 앱키 · 시크릿 · 계좌번호는 `account-link/new` 컴포넌트의 `useState`에만 둔다.
- 다음에 두지 않는다: 컨텍스트 · 전역 상태, 네비게이션 파라미터(네비게이션 상태는 직렬화 · 복원 대상이다), `kvStore` · SecureStore, TanStack Query 쿼리 키, `useMutation`의 `variables`(mutation 캐시가 보관한다).
- 등록은 `endpoints.ts`의 `linkAccount(body)`를 제출 핸들러가 직접 부른다. 본문은 제출 때 만들고 저장하지 않는다.
- 성공하면 화면이 닫히며 상태가 사라진다. 실패하면 시크릿 칸을 비운다.

### 5.2 로그 · 오류

- 이 기능의 코드는 `console.*`를 부르지 않는다.
- 오류 객체에는 서버 고정 문구(`ApiError.message`)와, 네트워크 오류면 `fetch`의 원인 예외가 담긴다. 요청 본문은 담기지 않는다.
- 클라이언트 검사 문구는 입력값을 되풀이하지 않는다.
- 앱에는 원격 오류 리포터가 없다.

### 5.3 입력 칸

- 시크릿은 가린다(`TextField`의 `secure`). 보기 버튼은 두고 처음에는 가린 상태다. 접근성 라벨은 `시크릿 보기` · `시크릿 가리기`다. 지금 `TextField`는 `비밀번호 보기`로 고정이라 라벨을 바꿀 수 있게 한다.
- 앱키는 가리지 않는다. 붙여 넣은 값을 눈으로 확인해야 한다.
- 세 칸 모두 `autoCorrect={false}` · `autoCapitalize="none"` · `spellCheck={false}` · `autoComplete="off"`, iOS `textContentType="none"`, Android `importantForAutofill="no"`. 키보드가 값을 학습하거나 추천하지 않게 한다.
- 붙여 넣기는 막지 않는다.

### 5.4 보이는 곳

- 계좌번호는 폼에서만 보인다. `GET /accounts`는 계좌번호를 주지 않는다.
- `EXPO_PUBLIC_API_BASE_URL`이 `https://`로 시작하지 않으면 폼 위에 `암호화되지 않은 연결이에요. 같은 네트워크나 port-forward에서만 실제 키를 넣으세요`를 둔다. 서버가 평문 HTTP로 열려 있다(API 설계 §6.4).

### 5.5 지키지 못하는 것

- 개발 빌드에서는 React 개발자 도구로 컴포넌트 상태를 볼 수 있다.
- iOS 앱 전환기 스냅샷과 사용자가 찍는 스크린샷에 폼이 찍힐 수 있다. 막으려면 패키지(`expo-screen-capture` 등)를 설치해야 하고, 이번에는 하지 않는다.

## 6. 데이터와 캐시

### 6.1 타입

```ts
type CollectionStatus = { state: string; as_of: string; failure_reason: string | null };

type LinkedAccount = {
  account_id: string;
  broker: string;
  label: string;
  account_type: 'GENERAL' | 'PENSION';
  source: string;
  env: 'REAL' | 'DEMO' | null;
  link_state: AccountLinkState;
  last_synced_at: string | null;
  last_collection: CollectionStatus | null;
};

type AccountListResponse = { accounts: LinkedAccount[] };
type LinkAccountResponse = { account_id: string; link_state: AccountLinkState; challenge: null };
```

- `state`를 문자열로 둔다. `collection_run.state`는 데이터 쪽 값이라 모르는 값이 올 수 있다(§3.1).
- 기존 `AccountRowData.last_collection: null`("언제나 null")은 서버가 이미 값을 채우므로 `CollectionStatus | null`로 고친다. 계좌별 화면은 이 필드를 그리지 않는다.

### 6.2 조회

- `GET /accounts`는 봉투가 없는 응답이라 `ScreenFrame`을 쓰지 않는다. 로딩 · 오류 · 빈 목록은 `account-link`가 직접 그린다(§3.2).
- 쿼리 키는 `['account-links']`다. `['accounts']`는 계좌별 뷰가 쓴다.

### 6.3 무효화

등록 · 해제가 성공하면 `account-links` · `accounts` · `summary` · `positions` · `allocation` · `realized-pnl` · `asset-change` · `cashflows` · `catalog` · `instruments`를 무효화하고 `alert-preview`를 캐시에서 지운다. 해제는 총자산과 계좌 필터(카탈로그), 종목의 보유 여부를 바꾸고, 입출금 계좌 선택은 카탈로그를 쓴다. 알림 미리보기도 보유 여부를 담지만, 디바운스하는 편집 화면은 마운트 때 다시 받지 않아 무효화로는 낡은 응답이 남는다. 등록은 첫 수집 전이라 뷰가 당장 바뀌지 않지만 같은 목록을 쓴다. 해제 `403`도 같은 범위를 무효화한다.

## 7. 테스트

`npx jest`와 `npx tsc --noEmit`이 통과해야 한다. RNTL · `serveRoutes` · `renderWithStack` · `renderWithNavigation`을 쓴다.

**픽스처**

- 계좌 탭과 점은 골든 `accounts.json`을 쓴다. 이 파일에 `STALE_ACCOUNTS`가 있어 점이 켜지는 경우가 된다. 꺼지는 경우는 그 안내를 뺀 사본이다.
- `GET /accounts`는 백엔드 골든이 없어 `src/fixtures/accountLinks.ts`에 DTO(`AccountDto` · `CollectionStatus`)를 보고 손으로 쓴다. §3.1 표의 다섯 조합을 담고, `env`는 `REAL` · `DEMO` · `null`을 하나 이상씩 담는다. id · 라벨은 가짜다. `AccountListResponse`로 받아 `tsc`가 모양을 검사한다.
- 자격증명 값은 `test-app-key` · `test-app-secret` · `00000000-01` 꼴만 쓴다.

**단위**

| 대상 | 확인 |
|---|---|
| 계좌번호 | 숫자만 남김 · 10자리에서 자름 · 하이픈 섞인 붙여넣기 · 표시용 하이픈 |
| 기본 라벨 | `01` · `22` · 그 밖은 없음 |
| 입력 검사 | 앞뒤 공백 · 1,024자 경계 · 라벨 30자 경계 · 이모지를 한 글자로 센다 |
| 상태 줄 | §3.1 표 전체 · 모르는 `state` |

**화면**

| 대상 | 확인 |
|---|---|
| 계좌 탭 | `계좌 연동 관리`가 있다 · 빈 상태에서도 있다 · 누르면 `account-link` · 점이 조건대로 켜지고 꺼진다 |
| 목록 | 상태 줄 문구 · `DEMO`인 행에만 `모의` · 빈 목록 · 조회 오류와 재시도 |
| 해제 | 시트 → `DELETE /accounts/{id}` → 목록 재조회와 §6.3 무효화 · `503`이면 시트 안에 오류 · `403`이면 목록 재조회 |
| 폼 | 클라이언트 검사 문구 · 라벨 미리 채움과 사용자가 고친 라벨 유지 · 요청 본문(snake_case, 공백 제거, 숫자 10자리, 체크하지 않으면 `env: "REAL"` · 체크하면 `"DEMO"`) · `202`면 목록으로 돌아가 새 계좌가 `연동 중` · 코드별 오류 자리와 문구 · 실패 시 시크릿만 비움 · 두 번 제출 안 됨 · `http` 주소면 경고 |
| 누출 | 성공 뒤와 실패 뒤 각각: query 캐시 · mutation 캐시 · 네비게이션 루트 상태를 문자열로 바꿔도 가짜 앱키 · 시크릿 · 계좌번호가 없다 · `console.log` · `info` · `warn` · `error` · `debug`가 그 값으로 불리지 않는다 · 성공 뒤 렌더 트리에 값이 없다 |

**수동 확인.** 구현이 끝나면 로컬 백엔드를 `portfolio.credentials.store=memory`로 띄우고 Expo 웹이나 시뮬레이터에서 가짜 키로 등록 · 해제를 한 번씩 해 본다. 서버 · 개발 서버를 띄우는 일이라 그때 승인을 받는다. 운영 서버에 실제 키로 등록하지 않는다.

## 8. 스펙을 이렇게 읽은 곳

스펙 문장은 고치지 않고 아래처럼 읽었다.

1. **첫 수집 전 상태** — 스펙 §10에 "연동했지만 첫 수집 전" 상태가 없다. 그 사이 계좌는 `position_line`이 없어 계좌별 뷰에 행이 없고, `EmptyReasonResolver`가 `CONNECTING`도 쓸 수 있는 계좌로 세어 첫 계좌 사용자는 `NO_HOLDINGS`를 받는다. 계좌별 화면은 빈 상태 아래의 `계좌 연동 관리`와 `account-link`의 상태 줄로 메운다. 요약 · 종목별 등의 빈 상태 문구는 이 설계에서 바꾸지 않는다.
2. **§10 계좌 연동 상태** — `기관 선택 / 인증 입력 / 추가 인증 요구 / 연동 실패·재시도 / 연동 성공`은 CODEF 경로 기준이다. KIS는 기관 선택과 추가 인증이 없고, 등록은 즉시 `202 CONNECTING`이며 성공 여부는 첫 수집 뒤 `last_collection`으로 보인다(API 설계 §9의 3과 같다). 이 설계는 KIS 상태만 다룬다.
3. **해제 확인의 자리** — §10은 `연동 해제 확인`을 계좌별 화면의 상태로 적었다. 해제는 계좌별 화면에서 들어가는 `account-link`에서 한다. 첫 수집 전 계좌는 계좌별 뷰에 행이 없어 계좌별 화면만으로는 해제할 수 없다.
4. **재인증 경로** — IA §3은 계좌 탭 점을 누르면 "재인증 경로가 같은 화면에 있다"고 적었다. KIS에는 재인증이 없어 재인증 버튼을 두지 않는다. 이월 계좌의 점은 그대로 켠다.
