# 앱 정보 구조 (App Information Architecture)

- **버전**: v1 (2026-09-27)
- **범위**: 두 기능(포트폴리오 종합 관리 · 매수·매도 타이밍 알림)이 한 앱에 놓이는 방식 — 탭, 화면 목록과 진입 경로, 푸시 딥링크, 배지, 첫 화면, 공통 이름
- **비범위**: 각 화면의 내용과 데이터(기능 스펙이 정의), 상태관리·디자인 시스템(구현 계획이 정의)
- **관련 자료**: [포트폴리오 종합 관리 스펙](./portfolio-management/2026-07-28-portfolio-management-spec.md) · [매수·매도 타이밍 알림 스펙](./buy-sell-timing-alert/2026-07-12-buy-sell-timing-alert-spec.md)

---

## 1. 원칙

**화면은 그 화면이 답하는 질문이 생기는 자리에서 들어간다.**

| 질문 | 생기는 자리 | 그래서 |
|---|---|---|
| 지금 내 자산은? 뭘 갖고 있나? 어디에 쏠렸나? | 앱을 연 순간 | 탭 |
| 요약에서 본 저 증감은 무엇이었나? | 요약·실현손익을 보던 중 | 스택 화면 (자산 변화) |
| 무엇이 울렸나? | 푸시·배지 | 푸시 → 울린 알림 상세 |
| 이 종목에 알림을 걸까? | 종목을 보던 중 | 종목 상세 → 새 알림 흐름 |
| 내가 뭘 걸어 뒀나? | 어디에도 딸리지 않음 | 탭 (알림) |

"내가 뭘 걸어 뒀나"는 포트폴리오의 어느 화면을 보다가 생기는 질문이 아니다. 알림은 보유하지 않은 종목에도 걸리므로 종목 화면에만 매달 수도 없다. 그래서 알림은 탭이다.

**배지는 누르면 그 내용이 맨 위에 보이는 자리에만 둔다.** 갈 곳 없는 점은 불안만 준다.

## 2. 화면 목록과 진입 경로

### 2.1 탭

`요약 · 종목 · 비중 · 계좌 · 손익 · 알림`

아이콘 없이 두 글자 텍스트만 쓴다. 여섯 개가 한 줄에 들어간다.

### 2.2 화면

| 화면 | 기능 | 형태 | 들어오는 곳 |
|---|---|---|---|
| 로그인 | 공통 | 탭 바깥 진입 화면 | 앱 시작(미인증) · 토큰 만료 |
| 요약 | 포트폴리오 | 탭 | 탭 · 로그인 직후 |
| 종목별 | 포트폴리오 | 탭 `종목` | 탭 · 계좌별 행(계좌 필터) |
| 비중 분석 | 포트폴리오 | 탭 `비중` | 탭 · 요약 `비중 →`(시장 축) |
| 계좌별 | 포트폴리오 | 탭 `계좌` | 탭 |
| 실현손익 | 포트폴리오 | 탭 `손익` | 탭 · 자산 변화 `실현손익 뷰 →`(기간) |
| 자산 변화 | 포트폴리오 | 스택 | 요약 `더보기 →` · 실현손익 하단 링크 |
| 종목 상세 | 포트폴리오 | 스택 | 종목별 행 |
| 계좌 연동·동기화 | 포트폴리오 | 스택 | 계좌별 |
| **알림** | 알림 | 탭 루트 | 탭 |
| **울린 알림** | 알림 | 스택 | 알림 `전체 →` |
| **울린 알림 상세** | 알림 | 스택 | **푸시** · 울린 알림 행 · 알림의 새로 울린 알림 행 |
| **알림 상세** | 알림 | 스택 | 알림의 내 알림 행 · 울린 알림 상세 `알림 보기` |
| **새 알림** | 알림 | 모달 스택 (아래) | 알림 `＋ 새 알림` · 종목 상세 `알림 걸기` · 알림 상세 `수정` |

**새 알림 흐름**

```
종목 선택 → 조건 선택 ─┬─ 프리셋 입력 ──┬─→ 공통 설정 → 저장 → 알림 상세
                       └─ 조건 만들기 ──┘
```

| 들어온 곳 | 시작 단계 |
|---|---|
| `＋ 새 알림` | 종목 선택 |
| 종목 상세 `알림 걸기` | 조건 선택 (종목이 채워져 있음) |
| 알림 상세 `수정` | 프리셋 입력 또는 조건 만들기 (값이 채워져 있음) |

모달로 여는 것은 흐름 전체가 한 번의 저장으로 끝나는 작업이라서다. 닫으면 들어온 자리로 돌아가고, 저장하면 알림 상세가 열린다.

### 2.3 알림 탭 루트

```
┌ 알림                         ＋ 새 알림 ┐
│ 새로 울린 알림 2              전체 →    │ ← 미확인 발화만. 없으면 블록 숨김
│  · 삼성전자 · 가격 도달 · 10:15         │
│  · 카카오 · RSI 과매수 · 9/26 종가      │
│ 내 알림                                 │
│  삼성전자  현재가 ≥ 70,000   감시 중 [●]│
│  카카오    RSI 3일 연속 ≥ 70 조건 충족 중│
└─────────────────────────────────────────┘
```

규칙(알림)과 사건(울린 알림)을 한 화면에 둔다. 배지를 보고 들어온 사용자가 탭 하나로 무엇이 울렸는지 보고, 같은 자리에서 그 규칙을 관리한다. 발화 전체 이력은 `전체 →`로 미룬다 — 루트 화면의 주인은 규칙 목록이다.

### 2.4 종목 선택

종목 선택은 **전 종목 검색**이다. 포트폴리오의 종목별 화면을 재사용하지 않는다 — 그 화면은 보유 행과 금액·필터·렌즈를 가진 뷰이고, 알림 대상은 보유 종목에 한정되지 않는다.

| 공유 | 공유하지 않음 |
|---|---|
| 종목 검색 API `GET /instruments?q=&held=` · 종목 행 컴포넌트(이름 · 종목코드 · 시장 배지) | 종목별 화면의 행·필터·정렬·렌즈 |

화면은 `보유 종목` 구역(검색어가 없을 때, `held=true`)과 `검색 결과` 구역으로 나뉜다.

### 2.5 보유 종목에서 알림 걸기

진입점은 **종목 상세의 `알림 걸기`**다. 종목이 채워진 채 새 알림 흐름의 조건 선택으로 들어간다. 종목을 보다가 생긴 질문이므로 종목 선택을 다시 거치지 않는다.

종목별 행이 아니라 종목 상세에 두는 것은 종목별 행의 탭이 이미 종목 상세로 가는 자리이기 때문이다. 행에 두 번째 동작을 붙이면 누를 곳이 둘로 갈린다.

## 3. 배지

| 자리 | 형태 | 뜨는 조건 | 누르면 |
|---|---|---|---|
| `알림` 탭 | 숫자 | 미확인 발화 수 (`GET /alert-events/unread-count`) | 알림 탭 루트 — 새로 울린 알림 블록이 맨 위 |
| `계좌` 탭 | 점 | 이월 계좌 또는 재인증 필요 계좌 존재 (포트폴리오 스펙 §7.5) | 계좌별 — 해당 계좌 행이 배지를 달고 있고 재인증 경로가 같은 화면에 있다 |

- 알림 탭의 수는 앱이 앞으로 올 때와 푸시를 받을 때 다시 받는다.
- 울린 알림 상세를 열면 그 발화가 읽음 처리된다. 알림 탭을 여는 것만으로는 읽음 처리하지 않는다 — 블록에 제목만 보이고 내용을 본 것이 아니다. 울린 알림 화면에 `모두 읽음`이 있다.
- 계좌 탭의 점은 숫자가 아니다. 알릴 것은 "낡았거나 조치가 필요한 계좌가 있다"는 사실이고 개수는 계좌별 화면의 행이 말한다.
- **점은 조치 경로와 함께 들어간다.** 계좌 탭의 점은 재인증·계좌 연동 화면이 앱에 서는 것과 같은 시점에 켠다. 조치할 곳 없이 점만 찍으면 갈 곳 없는 점이 된다.

## 4. 푸시 딥링크

### 4.1 경로

| 링크 | 여는 화면 | 스택 |
|---|---|---|
| `…://alert-events/{event_id}` | 울린 알림 상세 | 알림 탭 루트 위. 뒤로 가면 알림 탭 루트 |

푸시 페이로드의 `data.url`이 이 링크다(알림 스펙 §9.3). 링크는 발화를 가리키고 규칙을 가리키지 않는다 — 규칙은 그 뒤 수정·삭제될 수 있지만 발화는 그때 울린 내용 그대로 남는다.

### 4.2 앱 상태별 동작

| 앱 상태 | 동작 |
|---|---|
| 앞에 떠 있음 | 화면을 옮기지 않는다. 앱 안 배너를 띄우고 배지를 갱신한다. 배너를 누르면 울린 알림 상세 |
| 뒤에 있음 | 푸시를 누르면 울린 알림 상세 |
| 꺼져 있음 · 인증됨 | 실행 후 울린 알림 상세 |
| 꺼져 있음 · 토큰 만료 | 로그인 화면. **링크를 기억해 두었다가 로그인 뒤에 연다** |
| 다른 계정으로 로그인됨 | 서버가 `404`로 답하고 울린 알림 상세가 `찾을 수 없는 알림`을 보여준다 |

인증 상태에 따라 앱은 로그인 화면과 탭 묶음 중 하나만 그린다. 그래서 로그인 전에 받은 링크는 네비게이션 바깥에 보관했다가, 탭 묶음이 그려진 직후 한 번 열고 버린다. 로그인에 실패하거나 사용자가 다른 화면으로 가면 버린다.

---

## 5. 로그인 직후 첫 화면

**요약이다.** 미확인 발화가 있어도 화면을 옮기지 않고 알림 탭 배지로만 알린다. 사용자가 스스로 앱을 연 순간이라 늘 같은 자리에서 시작하는 편이 낫고, 알림은 배지가 충분히 말한다. 예외는 푸시로 열린 경우뿐이다(§4.2).

새 사용자는 계좌가 없으므로 요약의 온보딩이 첫 화면이다. 알림은 계좌 없이도 만들 수 있으므로 온보딩이 알림 탭을 막지 않는다.

## 6. 공통 이름

화면 문구 · 문서 용어 · 코드 식별자를 한곳에 둔다. 새 화면이나 개념을 추가하면 이 표에 먼저 올린다.

### 6.1 화면

| 화면 문구 (탭·헤더) | 문서 용어 | 코드 (`screen` · `view_key`) |
|---|---|---|
| 요약 | 요약 | `summary` |
| 종목 (탭) · 종목별 (헤더) | 종목별 | `positions` |
| 비중 (탭) · 비중 분석 (헤더) | 비중 분석 | `allocation` |
| 계좌 (탭) · 계좌별 (헤더) | 계좌별 | `accounts` |
| 손익 (탭) · 실현손익 (헤더) | 실현손익 | `realized-pnl` |
| 자산 변화 | 자산 변화 | `asset-change` |
| 종목 상세 | 종목 상세 | `instrument-detail` |
| 계좌 연동 | 계좌 연동·동기화 | `account-link` |
| 알림 | 알림 탭 루트 | `alerts` |
| 울린 알림 | 울린 알림 | `alert-events` |
| 울린 알림 (헤더) | 울린 알림 상세 | `alert-event` |
| 알림 상세 | 알림 상세 | `alert` |
| 새 알림 · 알림 수정 | 새 알림 흐름 | `alert-editor` |
| 대상 종목 | 종목 선택 | `alert-editor/instrument` |
| 조건 선택 | 조건 선택 | `alert-editor/trigger` |
| (프리셋 이름) | 프리셋 입력 | `alert-editor/preset` |
| 직접 조건 만들기 | 조건 만들기 | `alert-editor/composable` |
| 공통 설정 | 공통 설정 | `alert-editor/settings` |

탭 라벨은 두 글자로 줄이고 헤더는 뷰 이름을 쓴다. 탭 라벨이 뷰 이름과 다른 것은 폭 때문이며, 문서는 항상 뷰 이름으로 쓴다.

### 6.2 개념

| 화면 문구 | 문서 용어 | 코드 |
|---|---|---|
| 알림 | 알림 | `alert` |
| 울린 알림 | 발화 | `alert_event` |
| 장중 · 종가 | 평가 시점 | `cadence` (`INTRADAY` · `CLOSE`) |
| 돌파할 때마다 · 한 번만 · N분마다 다시 | 발화 방식 | `notify_mode` (`EDGE_REARM` · `ONE_SHOT` · `COOLDOWN`) |
| 감시 중 · 조건 충족 중 · 확인 불가 · 꺼짐 · 발화 후 종료 · 만료 | 알림 상태 | `status` + `last_result` |
| 프리셋 · 직접 조건 만들기 | 프리셋 · 조립형 | `PRESET` · `COMPOSABLE` |
| 종목 | 종목 | `instrument` |

"발화"는 화면에 쓰지 않는다. 사용자에게는 알림이 "울렸다".
