## 1. 수정주가 일봉 — 지금은 불가

안건이 요구한 네 가지(`instrument_id` 키·미국 일봉·300거래일·기업행위 보정) 중 어느 것도 지금 상태로는 못 준다. 막힌 지점이 셋으로 갈린다.

- **`instrument_id` 키**: ②종목 마스터 파이프라인이 아직 없어 `instrument_id` 자체가 존재하지 않는다. `symbol` 임시키만 있다.
- **300거래일 이력**: 기술적으로는 문제없다. KIS 기간별시세가 1회 100일 제한이라 3번 호출로 백필 가능.
- **기업행위 보정**: ⑤기업행위 파이프라인이 없어 `corporate_action`이 의도적으로 0행이다. 보정계수를 만들 원천이 없다.
- **미국 일봉**: 파이프라인 자체가 없다.

**제안.** 안건 1 본문이 이미 "보정 없이 먼저 열고 백엔드의 국내 가격제한폭 방어를 믿는" 트레이드오프를 수용했다. 데이터팀도 같은 전제로 움직이면, ②(바로 가능)부터 열어 `instrument_id`를 만들고, 국내 비보정 계열부터 제공하는 순서를 제안한다. 미국은 사용자 보유 종목만 최소로 시작. ⑤(기업행위)는 DART 소스 확정이 선행돼야 해서 별도 트랙으로 간다.

## 2. 투자자별 순매수 확정치 — 가능, 실측 완료

KIS Open API `FHKST01010900`(`/uapi/domestic-stock/v1/quotations/inquire-investor`)을 종목(005930)으로 직접 호출해 확인했다(`dataeng/bronze/get_investor_trend.py`).

- **이력**: 날짜 파라미터 없이 호출해도 **최근 약 30거래일치**가 한 번에 온다 — 안건이 요구한 "최소 30거래일"을 그대로 충족.
- **확정치 여부**: 응답에 확정/잠정 플래그 필드는 없지만, 호출 당일(T) 데이터는 포함되지 않고 **가장 최근 완결된 거래일(T-1)까지만** 온다. 장중 잠정치가 섞여 들어오는 구조가 아니다.
- **필드**: `frgn_ntby_qty`(외국인 순매수 수량)·`orgn_ntby_qty`(기관)·`prsn_ntby_qty`(개인) — 순매도는 음수로 옴. 금액 버전(`_tr_pbmn`, 단위 백만원 추정)도 같이 온다.
- **호출 단위**: 종목 하나씩(`FID_INPUT_ISCD`) — ①계좌 수집과 같은 호출 패턴.

장 마감 후 배치(⑧시세와 같은 시간대, 19:30 KST)로 당겨오면 다음 영업일 개장 전 도착 요건을 충족한다.

## 3. 장중 스냅샷 앱 DB 직접 적재 — 가능, 새 패턴으로 승인 요청

지금까지 모든 파이프라인은 "API → Bronze → Silver → reverse ETL → Postgres"였다. 이 안건은 레이크를 건너뛰고 Airflow KPO 파드가 `intraday_watchlist`를 읽어 Postgres에 직접 쓰는, **처음 생기는 두 번째 적재 경로**다.

데이터 파이프라인 지도의 엔진 구성표에 이미 있는 **ClickHouse("가격 차트·알림용 빠른 조회 캐시")가 정확히 이 용도**로 설계돼 있었다. 다만 ClickHouse가 아직 배포 안 됐고(매니페스트가 git에 없음, 노드에만 있음) 장중에만 의미 있는 컴포넌트라 지금 올리는 건 과하다. **제안**: 지금은 Postgres 직접 적재로 시작하고, ClickHouse를 실제로 올릴 때 이 경로를 옮긴다.

호출량도 전종목이 아니라 워치리스트 대상만이라 초당 호출 제한(3건/초) 안에서 5분 주기가 충분히 가능해 보인다(워치리스트가 수백 종목 규모를 넘지 않는다는 전제).

## 4. `market_data_run` — 가능

`collection_run`과 완전히 같은 패턴(상태 전이 테이블, 백엔드는 읽기만)이라 새로 결정할 게 없다.

## 5. `dim_market_calendar` 시각 컬럼 — 가능

⑥거래일 캘린더 파이프라인(계획 상태)에 `open_at`/`close_at` 두 컬럼만 추가하면 된다.

## 6. 종목 마스터 — 가능, 이미 최우선 진행 중

데이터 파이프라인 지도의 "팀 결정" 절이 ②종목마스터를 이미 "무료 소스라 키 필요 없음, 바로 가능"으로 분류해뒀다. 검색 인덱스만 요구 범위에 추가된다.

## 7. Expo 푸시 Secret + egress — 가능, 확인 완료

`argocd` 저장소를 확인한 결과 NetworkPolicy·CNI 정책이 전혀 없어 클러스터 egress는 기본 전체 허용 상태다. Expo 서버로 나가는 HTTPS 통신은 이미 열려 있다. Secret도 KIS/CODEF 자격증명과 같은 방식(`kubectl`로 직접 생성, 매니페스트는 이름만 참조)으로 추가하면 된다.

## 8. v1 Android 알림 제한 — 팀 공통 판단

데이터팀 파이프라인과 무관한 팀 디바이스 구성 문제다. 데이터팀 의견이 필요한 안건은 아니다.

## 함께 보는 블로커

안건들과 별개로, 데이터 파이프라인 지도가 지적한 **①계좌 수집의 블로커(계좌 자격증명 미입력, Postgres `data` 스키마 미합의)**가 안건 1·3·4·6에도 간접적으로 걸려 있다. `data` 스키마 자체가 없으면 안건 2·4·5·6 전부 reverse ETL 도착지가 없다 — 스키마 합의가 이 답변 전체의 선행조건이다.
